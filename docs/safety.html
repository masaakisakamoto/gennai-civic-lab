Safety principles

Public AI should be useful, explainable, and reviewable.

gennai-civic-lab treats safety as part of the system design, not as an afterthought. The project is built around small experiments, local testing, human review, and auditable workflows.

Core safety ideas

These principles guide the project before any AI app is considered for real-world use.

Do not rush into production

Start with local experiments, sample data, and limited review workflows before exposing systems to real users.

Keep humans in the loop

AI outputs should be treated as drafts or support material, especially in civic and public-sector contexts.

Avoid unsupported claims

When evidence is weak, the system should abstain or recommend checking with the responsible office.

Minimize sensitive logging

Operational logs should focus on metadata and avoid storing raw citizen text or personal information.

Evaluate continuously

Use evals, red-team smoke tests, and operational reports to detect regressions and unsafe behavior.

Make behavior inspectable

Prefer visible sources, trace identifiers, reproducible requests, and transparent quality checks.

Safety is not a feature. It is a workflow.

Public AI systems should be designed so that people can test them, review them, improve them, and stop them when confidence is not high enough.

What this project currently includes

gennai-civic-lab includes practical building blocks for safer experimentation.

Evaluation and red-team checks

Evaluation cases and red-team smoke tests help verify expected behavior, prompt-injection handling, and abstention behavior.

Observability

Health checks, local metrics, trace IDs, and operational reports help make behavior easier to inspect.

Local-first testing

Local Runner makes it possible to test AI app behavior before connecting it to real operational workflows.
