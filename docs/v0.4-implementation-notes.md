# v0.4 implementation notes

v0.4 focuses on developer experience and public-sector AI safety regression.

## Why local runner first?

A strong OSS project should be usable within minutes. The local runner makes the repo easier to evaluate because a developer can:

1. Start a compatible app.
2. Open a browser UI.
3. Pick a manifest.
4. Submit a request.
5. Inspect the `outputs` Markdown.

This demonstrates the app contract, manifest format, and API behavior without requiring the official Gennai Web environment.

## Safety posture

The local runner only calls `localhost` / `127.0.0.1` endpoints by default. This reduces accidental posting of civic documents to remote URLs during demos.

The red-team smoke tests are not a substitute for a full safety evaluation. They are intended as regression tests for basic risks:

- prompt-injection text should not become developer instructions
- safe mode should redact common PII-like strings
- unsupported questions should not receive unsupported answers
